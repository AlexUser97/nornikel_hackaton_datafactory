# «Кто твой шлиф» — импортонезависимый QC-ассистент металлографа

**Задача (официальное ТЗ, [task-3](https://nornickel-ai-hackathon.ru/task-3)):** по панорамным
снимкам оптической микроскопии аншлифов **классифицировать руду** — сегментировать сульфидные
**срастания** на «обычные» (крупные, слабо замещённые) и «тонкие» (существенно замещённые),
количественно оценить **тальк** и вынести класс: **тальк > 10% → тальксодержащая руда**,
иначе класс по преобладанию обычных/тонких срастаний. Выход: цветная маска
(зелёный=обычные, красный=тонкие, синий=тальк), таблица метрик, **текстовое заключение**,
PDF/JSON/CSV, пакетная обработка серии.

Реализация — модульный **офлайн**-сервис: сегментация → доли фаз (% + оценка
неопределённости) → классификация по ТЗ → отчёт. Доп. профиль «сталь + ASTM» сохранён как
расширение вне основной задачи. (XRD в задаче не используется — данных нет — и убран из прототипа.)

### Классификация сорта: обученная модель (T4)

На реальных данных кейса классы = папки (рядовые / труднообогатимые / оталькованные, ~1180
снимков). На выданном **Tesla T4** дообучен классификатор сорта — **EfficientNet-B0**
(open-license, ImageNet-претрейн + аугментации яркости/контраста под sim-to-real):
**F1_macro ≈ 0.87, AUC ≈ 0.96** на валидации (per-class F1: рядовые 0.88, труднообогатимые 0.89,
оталькованные 0.84 при recall 0.93). Скрипт обучения — [training/train_classifier.py](training/train_classifier.py).

Модель (`weights/sort_classifier.pt`, CPU-инференс) подхватывается автоматически и даёт
вердикт сорта; если весов нет — пайплайн честно откатывается на классическую эвристику по
долям фаз.

**Панорамы** ([shlif/tiling.py](shlif/tiling.py)): крупные снимки (до 10000×10000+, ТЗ)
обрабатываются плитками — полноразмерная сегментация без потери морфологии вкрапленников
и классификация с агрегированием нейросети по плиткам (взвешивание по содержанию рудной
фазы). Панорама 13712×10798 — за ~60 с (бюджет ТЗ 5 мин); включается флагом `--tile` /
чекбоксом «Крупная панорама», а для очень больших снимков — автоматически. Быстрый режим
без тайлинга (даунскейл, ~15 с) остаётся для обычных снимков.

**Сегментация под ТЗ** ([shlif/ore_petro.py](shlif/ore_petro.py)): маска в цветах ТЗ —
зелёный=обычные срастания, красный=тонкие, синий=тальк, тёмный=нерудный фон.

### Сегментация талька: обученный U-Net (T4)

По уточнению организаторов: важнее всего **класс** и **доли площадей** (доля талька, доля
срастаний); площади срастаний важнее попиксельной точности. Сорт «оталькованная» определяется
по доле талька (>10%), классификатор решает **рядовая/труднообогатимая**.

**Зоны оталькования выделяются целиком** (морфологическое замыкание в связную зону), а рудные
**вкрапленники срастаний ВНУТРИ талька сохраняются** отдельным классом (красный/зелёный поверх
синего) — они важны по ТЗ. Пайплайн отдельно считает **доли площадей**: тальк (зона целиком),
срастания (все вкрапленники), в т.ч. срастания внутри талька — в UI (карточка вердикта), PDF и CSV.

**Важно про разметку:** в датасете пиксельной разметки талька фактически НЕТ — «синие линии»
из описания оказались единичными указателями (0 замкнутых контуров на 1043 снимках). Поэтому
тальк-сегментация обучена **слабо-supervised на надёжных метках папок**: оталькованные руды
(>10% талька) — положительный сигнал (тёмная нерудная матрица = тальк), рядовые/труднообогатимые
— отрицательный (та же тёмная зона = силикаты). U-Net (`segmentation-models-pytorch`, ResNet-18,
open-license) учится отличать текстуру талька от силикатов. Скрипт —
[training/train_talc.py](training/train_talc.py), веса — `weights/talc_unet.pt`.

Обучение — на всех метках папок (все рядовые/труднообогатимые как негативы, чтобы модель не путала
тёмную замещённую матрицу труднообогатимых с тальком) + сильная фото-аугментация (яркость/контраст/
цвет/гамма — по рекомендации организаторов учитывать цвет пикселей и устойчивость к освещению).
Валидация честно на уровне снимка (пиксельного GT нет): доля талька → порог 0.15 → детекция
«оталькованной руды», **F1 ≈ 0.93** (recall 100%, FP ≈ 8%; ложные срабатывания на труднообогатимых
снижены с ~40% до 4%). Сквозная точность вердикта на свежих снимках — **~87%** (оталькованные 10/10,
рядовые 9/10, труднообогатимые 7/10; последняя пара — самое тонкое различие степени замещения).
Инференс на CPU ([shlif/talc_model.py](shlif/talc_model.py)); без весов/`smp` — фолбэк на текстуру.

**Прочие уточнения организаторов реализованы:** при доле талька > 10% срастания НЕ ищутся (класс —
оталькованная), зона оталькования берётся целиком; сегментатор дополнительно **разделяет сульфиды и
оксиды (магнетит) по цвету** (сульфиды тёплые/яркие, оксиды нейтрально-серые) — 5 классов
(тонкие/обычные срастания, тальк, оксиды, нерудный фон); доли площадей (тальк, срастания, оксиды) —
в UI/PDF/CSV.

**Позиционирование (по отчёту аналитического отдела v2):** не замена аттестованному
методу и не конкурент SEM-EDS (TIMA), а **воспроизводимый ассистент исследователя** —
быстрая предварительная оценка, снижающая субъективность, в форме протокола лаборатории.

**Ключевой дифференциатор — честность модели.** Для каждого предсказания считается
**оценка неопределённости**; зоны, требующие верификации, подсвечиваются эксперту
(human-in-the-loop). На «грязных» данных модель не врёт уверенно, а честно поднимает
риск (sim-to-real). Сводный статус согласован с числами: зелёный — только при высокой
уверенности И малой доле «не определено» И отсутствии спорных зон (иначе — «требует
верификации», отчёт v2 §6.1).

> Весь стек open-source, работает в закрытом контуре НИИ (профиль Гипроникеля, ISO 17025)
> без интернета. Телеметрия отключена. Профили: **сульфидная руда Ni-Cu** (по умолчанию) и
> **сталь/сплав (Fe)**.

## Запуск

### Требования

- **Python 3.11** (или новее 3.10+); ~2 ГБ свободного места под зависимости.
- GPU **не обязателен** — всё ядро считается на CPU. Docker — опционально.
- Интернет нужен **только на этапе установки** (скачать пакеты). В рантайме — не нужен.

### Вариант 1. Локально (рекомендуется для демо)

**1) Получить код и войти в папку проекта:**

```bash
git clone <repo-url> kto-tvoy-shlif && cd kto-tvoy-shlif
# либо распаковать архив и перейти в папку
```

**2) Создать виртуальное окружение и установить зависимости:**

Windows (PowerShell):

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

> Если `python` не находится — укажите полный путь к вашему Python 3.11, например
> `D:\Python311\python.exe -m venv .venv`. Лаунчер `py -3.11` использовать не
> обязательно (в некоторых установках он ссылается на несуществующий путь).

Linux / macOS:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

**3) Запустить дашборд:**

```bash
streamlit run app.py
```

Откроется браузер на `http://localhost:8501`. Дальше: слева **«🧪 Загрузить
демо-образец»** → **«▶️ Анализировать»** → читаете паспорт → **«📄 Экспорт PDF»**.

**Доступ с других ПК в сети НИИ** (сценарий «лаборант заходит из браузера»):
приложение уже слушает `0.0.0.0:8501` — коллеги открывают `http://<ip-хоста>:8501`
(узнать IP: `ipconfig` в Windows / `ip a` в Linux). Порт можно сменить:
`streamlit run app.py --server.port 8600`. Остановить — `Ctrl+C` в терминале.

### Вариант 2. Docker (одна команда, для развёртывания в контуре)

```bash
docker compose up            # первая сборка ~5–10 мин, дальше — мгновенно
```

Дашборд на `http://<ip-хоста>:8501`. Результаты пишутся в примонтированную папку
`./data`. Остановить — `Ctrl+C` или `docker compose down`. После сборки образа
интернет не требуется (можно перенести образ в закрытый контур: `docker save`/`load`).

### Вариант 3. CLI / пакетно (без UI — страховочный трос)

```bash
python cli.py --demo                                   # демо задачи ТЗ (срастания + тальк) → вердикт
python cli.py -i anshlif.tif --scale 0.18              # свой снимок (профиль ТЗ по умолчанию)
python cli.py -i panorama.jpg --tile                   # панорама плитками (полноразмерная маска)
python cli.py --batch ./samples --out ./reports        # пакетная обработка серии + batch_log.json
python cli.py --demo --evaluate                        # метрики против ground truth (IoU/HD/F1/AUC)
```

На выходе — `protocol_<имя>.pdf` (протокол по ГОСТ 17025) + первичные данные
`protocol_<имя>.json` и `protocol_<имя>.csv` в каталоге `--out`.
Полный список ключей: `python cli.py -h`. Основные:

| Ключ                                  | Назначение                                                        |
| ------------------------------------- | ----------------------------------------------------------------- |
| `-i, --image`                         | путь к снимку (jpg/png/tiff); либо `--demo` для синтетики          |
| `--profile`                           | профиль материала (по умолч. аншлиф руды; есть «сталь + ASTM»)     |
| `--scale`                             | масштаб µm/px (по умолч. 0.35)                                     |
| `--tile` / `--batch`                  | тайлинг панорам / пакетная обработка каталога                     |
| `--customer` / `--lab`                | заказчик и лаборатория в шапку протокола (ГОСТ 17025)             |
| `--corrupt {clean,mild,medium,heavy}` | демо-загрязнение снимка (sim-to-real)                             |
| `--runs`                              | число прогонов ансамбля неопределённости (по умолч. 5)           |
| `--out`                               | каталог для протокола (по умолч. `data/`)                         |

> Windows: если в консоли кракозябры вместо кириллицы/греческих букв (α, γ) —
> задайте `set PYTHONIOENCODING=utf-8` (cmd) или `$env:PYTHONIOENCODING="utf-8"`
> (PowerShell) перед запуском CLI. На дашборд и PDF это не влияет.

## Что на выходе (протокол испытаний)

- **Шапка протокола по ГОСТ 17025/58973**: лаборатория/адрес/аккредитация, уникальный №,
  даты, заказчик/объект/метод, блок **оценки неопределённости**, дисклеймер статуса метода, подписи.
- **Сегментация** с оверлеем и слоями: исходник / сегментация / карта неопределённости / зоны на верификацию.
- **Фазовые доли** в % с расширенной неопределённостью U(95%) + доля **«не определено»** (площадь под сомнением).
- **Гранулометрия зёрен** (µm); для сталей — дополнительно **балл ASTM (E112)** (для руд неприменим).
  Пометка ⚠, если структура слишком мелкая/зашумлённая для надёжной оценки.
- **Разделение сульфидов и оксидов** (магнетит) по цвету; **доли площадей**: тальк, срастания, оксиды.
- **Карта неопределённости** и список **зон, требующих верификации** экспертом.
- **Экспорт**: PDF-протокол по ГОСТ 17025 + первичные данные **JSON/CSV** (воспроизводимость).
  Тёмный интерфейс «Протокол испытаний» с бейджем общей уверенности.

## Архитектура

Монолит на одном хосте (под 24ч микросервисы = самоубийство). Всё в одном процессе,
хранилище — локальные файлы (`data/`). Единый контракт `analyze()`, против которого
написана вся обвязка (UI, метрики, PDF).

```
app.py            Streamlit-дашборд «Паспорт шлифа»
cli.py            CLI/пакетный режим (снимок -> PDF + JSON)
shlif/
  analyze.py      контракт analyze(): оркестратор всех модулей
  segmentation.py классический CV-сегментатор (multi-Otsu + watershed зёрен), soft-версия
  uncertainty.py  ансамблевая неуверенность (разброс по пертурбациям) + зоны на проверку
  metrics.py      фазовые доли + ДИ, размер зерна, ASTM, дефекты
  ore_classification.py  логика классификации руды по ТЗ (тальк/срастания) + заключение
  ore_petro.py    сегментатор под ТЗ: обычные/тонкие срастания + тальк (green/red/blue)
  annotations.py  разбор синей экспертной разметки (тальк/ROI) + инпейнтинг
  sort_model.py   инференс классификатора сорта (EfficientNet-B0, color-adaptation аугментация)
  talc_model.py   инференс сегментации талька (U-Net ResNet-18, фолбэк на текстуру)
  tiling.py       потайловая обработка панорам (полноразмерная маска + классификация)
training/         train_classifier.py, train_talc.py — обучение моделей на T4
  simto_real.py   «загрязнялка» (шум/блюр/контраст) — движок ансамбля и демо
  evaluation.py   метрики: IoU, расстояние Хаусдорфа (HD/HD95), F1, AUC
  viz.py          оверлеи, тепловые карты (matplotlib Agg)
  ui.py           тёмная тема дашборда: CSS + HTML-компоненты (бары, бейджи, карточки)
  report.py       PDF-протокол (reportlab, кириллица через DejaVuSans)
  io_utils.py     загрузка снимков, экспорт JSON/CSV, масштаб из метаданных
  demo_data.py    синтетическая микроструктура (для тестов/демо без данных)
  config.py       имена фаз, палитра, пороги, профили материала
tests/            pytest: контракт, метрики, неопределённость, тальк, классификация, PDF
```

### Контракт `analyze()`

```python
from shlif import analyze
res = analyze(image, scale_um_per_px=0.5, soft_segment_fn=ore_petro_segment)
# res: mask, class_names, phase_fractions{value,ci}, ore_class{verdict,rule},
#      proportions{тальк, срастания, оксиды}, conclusion, uncertainty_map,
#      low_conf_zones[{bbox,confidence,note}], defects, ... (форма стабильна)
```

Модели можно менять, не трогая обвязку. Классический OpenCV-сегментатор — честный
бейзлайн и фолбэк (работает мгновенно на CPU, без ML-весов, данных и интернета).

### Предобученные модели и точка ожидания данных

Предобученные модели разрешены заказчиком при **открытой лицензии** (SAM — Apache-2.0,
U-Net `segmentation-models-pytorch` — MIT). Подключаются без правки обвязки через хук:

```python
def my_soft_seg(img):        # обёртка предобученной модели
    return mask, prob        # mask: H×W int, prob: H×W×K float
analyze(image, scale_um_per_px=0.18, soft_segment_fn=my_soft_seg)
```

`analyze()` прогонит вашу модель через тот же ансамбль неопределённости, метрики
и PDF-протокол. По умолчанию используется классический сегментатор.

### Метрики качества (критерии заказчика)

Автопроверки решений нет; ориентир заказчика — **IoU и расстояние Хаусдорфа** (сегментация),
**F1 и AUC** (классификация фаз). Реализованы в `shlif/evaluation.py` и считаются против
ground truth. Разметки нет — берём истинные метки из синтетического генератора
(`synthetic_microstructure(return_labels=True)`), поэтому оценка честная и уже сейчас:

```bash
python cli.py --demo --evaluate              # чистый образец
python cli.py --demo --evaluate --corrupt heavy   # sim-to-real: метрики честно падают
```
Пример (классический бейзлайн, синтетика): mIoU ≈ 0.85, HD95 ≈ 16 µm, F1 ≈ 0.92, AUC ≈ 0.97;
на загрязнённом снимке mIoU/F1 падают. По фазам виден «трудный» бейнит (IoU ниже) — метрика
подтверждает известную неоднозначность бейнит↔перлит. В дашборде — панель «🎯 Валидация на
синтетике» для демо-образца. Те же функции применяются к реальным разметкам без изменений.

### Как считается неуверенность

Мягкая (вероятностная) сегментация даёт распределение по фазам на каждом пикселе;
ансамбль лёгких фотометрических пертурбаций усредняет распределения. Неуверенность =
энтропия усреднённого распределения. Внутренности фаз уверенны (~0), границы и
размытые/зашумлённые зоны — спорны. Чем грязнее снимок, тем выше средняя неуверенность.

### Проверка на реальных данных

Пайплайн прогнан на реальных public-domain снимках сталей (Wikimedia Commons:
пластинчатый перлит, заэвтектоидная сталь со скана-полутоном). Сегментация
осмысленно выделяет цементитную сетку по границам зёрен, а карта неуверенности
честно подсвечивает зашумлённые зоны скана. Крупные снимки автоматически
прореживаются до рабочего разрешения (с пересчётом µm/px) и чистятся от растра.
На мелкодисперсной/пластинчатой структуре балл ASTM физически невычислим — тул не
выдаёт «красивое число», а помечает оценку зерна как ненадёжную. Тесты на реальных
снимках: `tests/test_real_samples.py` (пропускаются, если фикстуры не выкачаны).


Покрывают форму контракта, суммирование долей, диапазон неопределённости, рост
неопределённости при загрязнении (sim-to-real), логику классификации сорта, сегментацию
талька, тайлинг панорам, устойчивость на реальных снимках и генерацию PDF.

## Практики из смежных датасетов

Применены приёмы из открытых датасетов сегментации аншлифов руд:
- **LumenStone** (МГУ, оптическая микроскопия аншлифов, пиксельная разметка минералов + задача
  color-adaptation): сильная **цвето-световая аугментация** классификатора под разные условия
  съёмки месторождений → лучше обобщение рядовая↔труднообогатимая.
- **Lunar mare basalts SEM** (Zenodo, two-stage *сегментация → классификация по модальным долям*):
  подтверждает нашу архитектуру и мотивирует классификацию сорта с опорой на **доли фаз**
  (сульфиды/оксиды/тальк), а не только на сырые пиксели.
